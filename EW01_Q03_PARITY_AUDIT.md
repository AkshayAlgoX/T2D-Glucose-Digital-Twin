# EW-01 Q0-03 Parity Audit

## 1. Exact Q0-03 Definition
Q0-03 is direct in-process parity of the locked functions on legitimate VAL inputs. It does NOT mean running the top-level `evaluate_run.evaluate()` script on VAL. Instead, the locked evaluator's internal functions (such as `causal_decision_mask`, `patient_stats`, `event_counts`, etc.) are imported and called directly on the validation dataset to establish a reference, which is then mathematically compared to the EW-01 harness output.

## 2. Exact VAL Inputs Used
- Data split: `val` list in `runs/pr_tft_ablation_arm_d/split.json`.
- Frozen artifacts: The associated checkpoint, normalizer, calibrator, `canonical_meal_log.npz`, and `model_selection_rule.json`.

## 3. Exact Reason for Previous IdentityError
The previous parity test inappropriately invoked `evaluate_run.evaluate()` while mocking `split.json`. Because `evaluate_run.py` iterates over the entire split to establish the global meal-log hash, injecting the validation split into the test split changed the deduplicated patient population, breaking the `meal_log_sha256` identity check. 

## 4. Whether the Cause Was Fixed Legitimately
Yes. The mocked test has been entirely discarded. The current parity test correctly imports and uses the split-agnostic locked functions directly on the legitimate VAL inputs without bypassing any identity or provenance checks.
